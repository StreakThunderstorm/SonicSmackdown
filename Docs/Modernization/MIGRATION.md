## Anti-aliasing compatibility

UE5.8 treated `r.DefaultFeature.AntiAliasing` as an unregistered dummy variable, silently using the engine's default
method. The project now explicitly selects FXAA through `r.AntiAliasingMethod=1`. Thirteen unchanged stage Blueprints
contain `r.PostProcessAAQuality 6`; UE5.8 no longer registers that command. Their requested maximum FXAA quality is
now supplied centrally by `[ConsoleVariables] r.FXAA.Quality=5`, which also applies in Shipping.

Epic's [UE4.27 scalability reference](https://dev.epicgames.com/documentation/en-us/unreal-engine/scalability-reference?application_version=4.27)
identifies 6 as the old maximum FXAA quality. Installed UE5.8 `PostProcessAA.cpp` defines 5 as its maximum and
`FXAAShader.usf` maps it to preset 39. This preserves the selection/quality intent; it does not prove exact pixels match
the unavailable customized UE4 engine. FXAA permutations are compiled independently of these runtime settings, so
the change does not require recooking the unchanged maps.

The repeated packaged Development smoke logged effective values 1 and 5, passed all 44 checks and produced five
reviewed captures with visible colored fighters/stage and no shader-preparation overlay. It used runtime overrides
against the earlier staged test package; the final Shipping archive then staged the actual updated configuration.
The old map commands remain known no-ops and still log a warning; no stage graphs were resaved or rewired.
