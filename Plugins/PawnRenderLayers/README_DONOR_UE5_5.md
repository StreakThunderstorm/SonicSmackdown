# Pawn Render Layers prototype

UE 5.5.4 desktop prototype for independent pawn group ordering and 0â€“100% orthographic flattening. No engine installation files, existing plugin sources, material assets, or gameplay assets are edited. The game module connects its existing team ordering functions to this plugin.

## Try it

1. Restart the editor after building. The plugin is enabled by default. The startup log should contain `UE 5.5.4 pawn layer shader overlays enabled`.
2. Add a **Pawn Render Layer Component** to each fighter Blueprint. Initially test with ordinary, non-Nanite meshes and materials that do not already apply the old flattening/depth function. The old material deformation is not automatically removed.
3. Set **Flattening Percent** independently on each fighter: 0 preserves perspective; 100 projects the fighter at its root's camera distance, removing depth-dependent perspective scaling. This is projection flattening, not physical mesh compression.
4. **Auto Assign Layer** defaults on: separate instances (including subclasses of the same base Blueprint) receive unused starting layers. Layer 0 is the nearest character layer; positive layers sit farther back. Runtime foreground swaps renumber the selected root to 0 and shift the remaining groups behind it. The available range is 0–200. Disable auto assignment when deliberately using matching numeric layers. Call **Bring To Front** on the attacking fighter's component to reorder the registered groups. **Send To Back**, **Set Layer**, **Set Flattening Percent**, and **Set Group Layering Enabled** are Blueprint-callable.
5. Pawn components, socket/component attachments, attached actors and actor-owned descendants are discovered each tick, including fighter-owned projectiles. Socket-spawned effects are discovered even when Unreal assigns their component to another actor. FrameData Niagara actors, hit sparks and projectile death effects register automatically with their spawning actor’s nearest group before playback. Completed pooled effects are released; an owned/attached Niagara effect automatically rejoins when activated again. No binding node is needed for those paths. An unrelated location-spawned effect without ownership or attachment still needs **Bind Effect** (`BGNiagaraRenderGroupComponent`) with its spawning pawn, because position alone does not identify its source. Other primitives can use **Register Effect** and **Unregister Effect** directly. Unregister suppresses rediscovery until explicit registration, or reactivation of an owned/attached Niagara effect.
6. To compare projection alone, disable **Group Layering Enabled**. Flattening remains active and the original translucency priority is restored.

`ABGTeamManagerPawn::SendToForegroundLayer` and `SendToBackgroundLayer` now route fighters with this component through the plugin. Existing hit, tag and projectile calls continue to work. Each team retains active fighter > Assist 1 > Assist 2 visual ordering (with ascending numeric layer indices); foreground/background moves include the fighter’s owned/attached meshes and effects without changing its flattening. Fighters without the component retain the old material/Niagara depth behavior. Add the component to the fighter base Blueprint to opt in; no spawning changes are needed. Actor children with their own component inherit their nearest owner/attachment group's ordering, flattening and projection anchor by default. Their components manage their own primitives and effects. Set **Inherit Parent Group** off for an independent group. Blueprint subclasses are separate actor instances; class inheritance alone does not share a group. Use **Get Layer** and **Get Flattening Percent** for effective runtime values; the editable properties store local defaults.

Call **Set Shared Group** on a pawn's component with another pawn's component to explicitly join that group, even without ownership/attachment. Passing null restores automatic inheritance. Cycles and cross-world references are refused. Ordering and setting flattening through any member affects the entire shared group. Runtime owner/attachment changes are resolved each tick; explicit sharing and setters update existing members immediately. Explicit duplicate membership is refused until the former group releases the component.

## Rendering

The startup module copies engine/private shader sources and PrExtendedShadingPro/private shader sources into this plugin's ignored `Intermediate/ShaderOverlay/5.5.4` directory. It patches the copies, checks exact anchors, and installs more-specific virtual shader directory mappings. It does not modify shader type memory or replace existing directory mappings. PrExtendedShadingPro remains responsible for its existing shader-type redirection.

The patch covers the conventional base pass, full and position-only depth prepasses, and velocity vertex shaders. Tagged geometry is rendered through those normal passes, without per-pawn captures or render targets. PrExtendedShadingPro's original base-pass pixel shader and shading logic are preserved.

Custom primitive data slots **28â€“35** are reserved. Existing occupied slots are skipped with a warning. Other custom primitive data is retained, including PrExtendedShadingPro's slot 3. Reserved values and translucency priorities are restored when membership ends.

Layering allocates disjoint reversed-Z depth ranges to the distinct registered layer values, retaining layer 0 as the reference even when it is unoccupied. Two active layers each receive almost half the available foreground range instead of reserving tiny fixed bands for all 201 possible indices. Layer 0 is the zero-offset reference within the protected foreground range; positive layers move farther back. Equal numeric layers deliberately use the same band. The foreground edge stays fixed at device depth 0.95 as groups join or leave. This is relative character depth, not world-space depth zero or removal of the stage protection. Gaps between bands prevent separate groups from interpenetrating. The default foreground device-depth interval is 0.5 through 0.95, ahead of ordinary stage surfaces farther than twice the engine near clip distance. **Layer Plane Distance** defaults to 0; a positive value changes the far boundary of that interval and is clamped to at least twice the engine near clip distance. Untagged near-camera geometry can still occlude fighters. Custom per-camera near clip overrides are not yet supported.

Every shared group projects its primitive bounds onto the primary camera axis to determine its near/far extent, including children and detached effects. Clip Z and W are affine functions of camera depth, preserving triangle planes and self-occlusion through the 0–100% projection transition. The helper changes clip W rather than scaling each vertex's clip XY nonlinearly. This also gives orthographic geometry orthographic attribute interpolation. The shader uses the same helper in base, depth, position-only depth and velocity passes. This synthetic depth is independent of group flattening.

Flattening uses the first player camera and pawn root as its projection reference. Translucent components receive group sort priorities; opaque components use the patched depth ranges. The helper bypasses orthographic views and untagged primitives.

Editor/game preview worlds, including the Frame Data editor viewport, do not apply runtime group membership or projection. Their saved layer and flattening settings remain editable. Component ticks, effect registration, setters and teardown safely skip subsystem access when no layer subsystem is available. `PawnRenderLayers.Groups.PreviewWorldSafety` covers both preview world types, ticks before BeginPlay, explicit lifecycle calls and preservation of existing primitive shader data and translucency priority.

Translucent and additive Niagara vertices are constrained to their assigned group band after projection. Within the reported bounds, the affine mapping is preserved. Overflowing vertices are limited to the band's edges so particle camera offsets, underestimated bounds and material deformation cannot spill into another group's depth range. Opaque depth fitting remains affine to preserve close-up surface separation. Overflowing transparent geometry can lose depth separation within its own group; accurate bounds are still preferable.

## Prototype limitations

- Single primary perspective camera. Split screen, stereo, alternate perspective captures, and view-specific reference planes are not supported.
- Nanite and specialized render paths are not patched. Conventional skeletal/static meshes and Niagara shader permutations are the initial scope.
- Compilation of Niagara sprite/ribbon/mesh material permutations does not prove every renderer supplies the component's custom primitive data correctly; visual validation is required.
- Depth bands change the depth buffer. Deferred position reconstruction, stage intersections, SSAO, screen-space reflections, depth fades, refraction, fog, decals, ray tracing, and lighting need visual validation or additional integration. The project's existing forward shading is a simpler initial target.
- Shadows retain their original geometry. Frustum/HZB occlusion culling retains original bounds, which can disagree with projected geometry. Test with `r.AllowOcclusionQueries 0` and `r.HZBOcclusion 0` when diagnosing disappearing groups; this plugin does not change those global settings.
- Velocity shaders use current group parameters with previous camera/vertex positions. Animated flattening, camera-relative reference changes, and layer swaps can produce incorrect temporal history. Prefer FXAA or no temporal AA for initial validation.
- Materials with pixel depth offset or existing flattening/depth modulation can conflict with synthetic layers. Truly coplanar surfaces still need an authored separation; the plugin does not decide which coincident surface should win.
- Depth fitting relies on primitive bounds. Set adequate skeletal/Niagara bounds and bounds scale for material world-position offsets. Opaque geometry outside its supplied bounds can spill outside its group's band; translucent Niagara overflow is constrained as described above. Very large depth spans and many active layers still reduce depth precision.
- Editor startup overlays are version-gated to 5.5.4 and fail without installing mappings if anchors or directory ownership differ. Cooked/package behavior remains to be verified. Shader changes require an editor restart and shader recompilation.
- The first prototype discovers attachments every frame and prioritizes correctness over membership-update optimization. Sublayers are not implemented. Arbitrary Blueprint or engine spawns outside the hooked game/FrameData paths need an explicit **Bind Effect** call because a location alone does not identify the spawning pawn.

## Verification

Build `BoltGameEditor Win64 Development`. Run the `PawnRenderLayers` automation filter in a graphics-enabled editor. The group test covers automatic instance allocation, owned/attached inheritance, explicit sharing and cycle rejection, ownership transfer, foreground swaps, independent flattening, detached effect registration/reuse, preservation of unrelated data, and teardown restoration. The shader test compiles ordinary opaque, masked, translucent, and additive materials for skeletal meshes and Niagara sprites/ribbons/mesh particles. The image test reads rendered pixels to verify that a closer untagged background occludes unlayered geometry but not layered fighters, foreground swaps, perspective versus orthographic widths, and surfaces separated by 0.01 units at normal/close camera distances with 0%, 50% and 100% flattening. Its scene capture is a test fixture, not the plugin's runtime rendering backend. Rendering tests are skipped under NullRHI.

Verified on UE 5.5.4 with this project's D3D12/forward/MSAA configuration: editor build passed; all three tests passed, including the depth separation regressions. Foreground swaps changed the overlap pixel from red to green. The two fixture meshes measured 39/22 pixels wide at 0% flattening and 30/30 pixels at 100%. Character animation, actual Niagara systems, temporal history, and cooked builds still require verification.

The `BoltGame.Rendering.TeamLayerIntegration` test exercises the actual team manager functions with two three-fighter teams, swaps both teams in both call orders, preserves their internal order and flattening, and verifies newly spawned owned effect discovery.

The `BoltGame.Rendering.NiagaraGroupInheritance` test covers custom and standard FrameData Niagara actors, explicit source binding for detached components, completion cleanup, reuse by another fighter, rollback resurrection, duplicate binding, and tracker teardown. Its Niagara components use completion delegate fixtures; real system rendering still requires visual validation. FrameData exposes a generic actor-spawn notification consumed by the game module, keeping render-layer dependencies out of the framework module. Its pooled spawner updates actor ownership on every reuse.

This test also covers foreign-owned socket components, automatic membership, detachment and reattachment to another fighter. `BoltGame.Rendering.ArcusEffectAssets` loads the actual eye/slash systems and checks that their materials enable hardware depth testing. Those authored materials still contain the old `OrthoBlend` flattening logic, which is not removed by this plugin.

`BoltGame.Rendering.RenderedNiagaraGroups` uses a transient copy of the actual Arcus slash system with an ordinary unlit translucent fixture material. It verifies rendered foreground/background swaps, automatic reactivation after release, manual unregister exclusion, and group isolation with intentionally underestimated particle bounds at 0%, 50% and 100% flattening. Source Niagara and material assets are not changed. The eye system produced no baseline pixels in this isolated scene, including with layering disabled; its authored appearance and sorting remain to be verified in the game. These checks prove the plugin's normal-material Niagara path, rather than compatibility with the old material-based flattening.

Final automatic-effects verification: the normal BoltGameEditor Win64 Development build passed, followed by all seven tests in the BoltGame.Rendering and PawnRenderLayers filters on D3D12. The transient Arcus slash fixture rendered 2457 foreground pixels and zero pixels behind the foreground group. Socket discovery/transfer and pool reactivation checks passed, along with the existing opaque close-up depth-separation checks. The authored eye effect still needs in-game visual verification.

The layer convention now starts at foreground layer 0 and increases toward the background. Existing explicit numeric assignments must follow this convention; saved negative values clamp to 0 at registration. Team foreground/background hooks, shared groups and Niagara sort priorities use the same convention. World transforms and projection flattening are unaffected.

Zero-baseline verification: BoltGameEditor Win64 Development built successfully and all seven BoltGame.Rendering/PawnRenderLayers tests passed on D3D12. Checks include zero-based automatic assignment, nonnegative layer limits, foreground swaps, a fixed layer-zero reference, positive layers behind an unoccupied zero reference, inherited effects, both team hook call orders, rendered Niagara swaps, stage occlusion protection and close-up surface separation.

Preview crash verification: BoltGameEditor Win64 Development built successfully and all eight BoltGame.Rendering/PawnRenderLayers tests passed on D3D12, including PreviewWorldSafety. An offscreen full editor session opened Adelaida's FD_Adelaida_Normals editor, ran 120 Slate ticks, closed and reopened it, ran another 120 ticks, and exited cleanly without saving assets. The build, automation and editor checks are recorded in Saved/Logs/PawnRenderLayersPreviewFixBuild.log, PawnRenderLayersPreviewFixTests.log and PawnRenderLayersPreviewSmoke.log.
